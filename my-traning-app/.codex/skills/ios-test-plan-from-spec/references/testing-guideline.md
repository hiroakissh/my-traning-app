# iOS SwiftUI + SwiftData テスト指針（簡易）

- **優先度**: P0=致命的、P1=主要フロー、P2=拡張/非機能。ハッピーパスと保存系はP0で必須。
- **DI徹底**: Repository/Serviceはprotocol経由で注入し、テストではインメモリSwiftDataまたはモックを使用。
- **状態管理**: @Observable + @MainActorなViewModelを主導。副作用はメソッドに閉じ込め、ViewからはTaskで呼び出す。
- **永続化**: SwiftDataのCRUDをインメモリコンテナで検証。ソート・フィルタ・ユニーク制約のテストを最低限行う。
- **エラー/オフライン**: リトライやエラー表示のUI状態遷移を必ずカバー。ネットワーク想定があればオフライン時のガードを追加。
- **アクセシビリティ**: 主要ボタンや入力欄のラベル/フォーカス順を確認。Dynamic Typeで崩れないかスナップショットを取る。
- **自動化**: XCTest + SwiftData用のユーティリティを共有し、テスト間でコンテナをクリーンに保つ。
