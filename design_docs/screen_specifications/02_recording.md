# 2. 記録画面

## 2.1. 画面概要

トレーニングの内容を詳細に入力・記録するための画面。素早く、かつ正確に記録できるUIを目指す。

## 2.2. 表示項目

-   **日付選択:**
    -   トレーニング日を選択するピッカー（デフォルトは今日）。
-   **種目選択エリア:**
    -   「種目を追加」ボタン。
    -   追加された種目のリスト。
-   **種目ごとの入力フォーム（リスト形式）:**
    -   **筋トレの場合:**
        -   種目名（テキスト入力、過去の履歴からサジェスト機能）。
        -   セットごとの入力フィールド（セット番号、前回の記録表示、重量、回数）。
        -   「セットを追加」ボタン。
    -   **ランニングの場合:**
        -   距離入力フィールド。
        -   時間入力フィールド。
        -   ペース（自動計算して表示）。
-   **タイマー:**
    -   セット間の休憩時間を計測するためのタイマー。
    -   「スタート/ストップ」「リセット」ボタン。
    -   プリセット時間（例: 60秒, 90秒）ボタン。
-   **保存ボタン:**
    -   画面上部または下部に配置された「保存」または「完了」ボタン。

## 2.3. 機能要件

-   **種目追加:**
    -   「種目を追加」をタップすると、種目タイプ（筋トレ、有酸素など）を選択するモーダルが表示される。
    -   種目タイプを選択すると、対応する入力フォームがリストに追加される。
-   **入力補助:**
    -   種目名を入力する際に、過去のトレーニング履歴から種目名をサジェストする。
    -   セットごとの入力フィールドには、同種目の前回のトレーニング記録（重量や回数）をプレースホルダーや参考値として表示する。
-   **タイマー機能:**
    -   タイマーは画面下部に常に表示され、他の操作を妨げない。
    -   時間が経過すると、音やバイブレーションで通知する。
-   **データ保存:**
    -   「保存」ボタンをタップすると、入力されたすべてのトレーニングデータを`TrainingLog`モデルとしてSwiftDataに保存する。
    -   保存が完了したら、前の画面（ホーム画面など）に戻る。

## 2.4. データ要件

-   `TrainingLog` (Domain/Models): 新しく作成または更新されるトレーニング記録。
-   `ExerciseDefinition` (Domain/Models): 過去に実行した種目のリスト（サジェスト機能用）。

## 2.5. ヘルスケアデータ連携

-   **取得開始タイミング:** 「記録を開始」ボタン押下時刻を基準にHealthKitへクエリし、セッション開始以降のデータを取得する。
-   **想定する取得データ:**
    -   心拍数（平均/最小/最大）
    -   アクティブエネルギー消費量・安静時エネルギー
    -   歩数
    -   移動距離（ウォーキング/ランニング）
    -   VO2Max（対応デバイスのみ）
    -   HRVやストレス指標（将来拡張）
-   **表示/利用方針:**
    -   記録画面内に取得ステータスとサマリー（例: 平均心拍数、消費カロリー合計、歩数など）を表示。
    -   保存する`TrainingLog`にヘルスケアサマリーを添付し、履歴やAIプラン作成時に活用できるようにする。
