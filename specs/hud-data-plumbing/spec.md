# HUDデータ整備 仕様

## 概要
ホーム/履歴/記録の各画面で必要となる進捗データをドメイン層に整備する。プラン表示用のモデル（Plan/PlanSuggestion/PlanProgress）、記録中の進捗計算を担う RecordingSessionState、履歴サマリを返す TrainingLog グルーピング・統計ヘルパーを追加し、UI がダミー値ではなく構造化データを参照できる状態を作る。

## 背景
- ホーム画面のプラン進捗や履歴サマリはプレースホルダー文言で、実データを供給するドメインモデルが存在しない。
- 記録画面では時間/距離/カロリー/心拍の進捗を計算する仕組みがなく、タイマーや HealthKit 連携を追加しても UI に渡す値の入れ先がない。
- History/ホーム向けの集計要件（カレンダー/分析表示）は TrainingLog 単体では満たせず、週次・日次での集計ヘルパーが必要。

## 目標
1. Plan/PlanSuggestion/PlanProgress のドメインモデルを追加し、画面仕様（ホームの進捗ウィジェット、プランニング一覧）のデータ要件を満たす。
2. RecordingSessionState を用意し、時間/距離/カロリー/心拍サンプルから進捗率と平均心拍を計算できるようにする。
3. TrainingLog を週次・日次にグルーピングし、総時間・ボリューム・目的別集計などを返すヘルパーを提供する。

## 非目標
- HealthKit や実データ取得ロジックの実装（ダミー値を置き換えるのは別イテレーション）。
- SwiftData 永続化や UI 差分描画の最適化。
- プラン再生成や編集 UI の実装。

## ユーザーストーリー
- ホームの進捗ウィジェットを確認する利用者として、長期目標に対する達成率や継続日数が実データで表示されてほしい。
- 記録中の利用者として、時間や距離、消費カロリー、平均心拍がどれだけ目標に近づいたかをリアルタイムで知りたい。
- 過去のログを分析する利用者として、週ごとの運動時間やボリューム、目的別の実施回数を把握したい。

## 受け入れ条件
1. Plan/PlanSuggestion/PlanProgress をシリアライズ可能なモデルとして Domain 配下に追加し、目標値と進捗率（0〜1でクランプ）を保持できる。
2. RecordingSessionState は時間・距離・カロリー・心拍の進捗を計算し、目標が未設定の場合は nil を返す。心拍はサンプルの平均で進捗率を算出する。
3. TrainingLog グルーピングヘルパーは週次・日次でログをまとめ、総時間（秒）と筋トレボリューム（重量×回数、ウォームアップ除外）を返す。
4. 上記の計算を検証するユニットテストが追加され、`swift test` が成功する。

## 未解決事項
- プラン進捗の目標単位（重量/時間/回数/体重など）の網羅性。今回のモデルでは汎用メトリクスとして扱い、画面側でのアイコンや表示単位は次フェーズで調整する。
