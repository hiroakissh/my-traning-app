# プランアクティブ状態管理 仕様書

## 概要
AIが返すプラン生成テキストを設計ドキュメントの画面構成（長期/中期/短期セクション）に沿った`PlanSuggestion`へマッピングし、採用したプランをSwiftDataに永続化してアプリ起動後も「アクティブプラン」として表示・切り替えできるようにする。プランニング画面ではアクティブプランを起点に、再提案（再生成）と他プランへの変更を行えるフローを提供する。

## 背景
- 現状の`AIWorkoutPlanner`はAI応答を長い文字列として保持しているだけで、画面仕様にある「長期/中期/短期」表示を行うための構造化がない。
- 採用済みプランを保存する永続レイヤーが存在せず、アプリ再起動時にプラン状態がリセットされる。
- プランニング画面は「再生成」ボタンとテキスト表示のみで、アクティブプランの提示・他プラン候補の提示・プラン変更の一連フローが欠けている。

## 目標
1. AI応答文字列を画面仕様のセクションに対応する`PlanSuggestion`へマッピングするヘルパーを実装する。
2. 採用したプランをSwiftDataへ保存し、最新のアクティブプランを読み出せる`ActivePlan`モデルを追加する。
3. プランニング画面でアクティブプラン表示、再提案、他プラン一覧、プラン変更フローを提供する。
4. ホーム画面にアクティブプランの要約を表示し、プラン状態を横断的に共有する。
5. マッピングと永続化フローをカバーするユニットテストを追加し、既存テストと併せて実行できることを確認する。

## 非目標
- ユーザー独自のカスタム編集（手動での種目編集やカレンダー生成）やHealthKit同期の実装。
- AIプロンプトテンプレートやFoundation Modelクライアントの大幅な拡張。
- Apple WatchやWidget側のプラン同期。

## ユーザーストーリー
- 利用者として、採用中のプランをアプリを閉じても保持し、プランニング画面でいつでも確認したい。
- 利用者として、AIが提示した複数プランから気に入ったものを選び、後から別のプランに切り替えたい。
- 利用者として、再提案を行ったときに最新の候補と現在のアクティブプランを比較できる表示がほしい。
- 利用者として、ホーム画面でも現在の目標とプラン概要を簡潔に確認したい。

## 受け入れ条件
1. `generatePlan`の応答から`PlanSuggestion`が3セクション（長期/中期/短期）に分類され、見出しがない場合でも汎用プランとして1件以上生成される。
2. プランニング画面でアクティブプランがカード表示され、再提案後に表示される別候補を選択してアクティブプランを更新できる。
3. 採用したプランはSwiftDataに保存され、アプリ再起動後も最新のプランが`@Query`経由で取得できる。
4. ホーム画面でアクティブプラン概要が表示され、未設定時は「プラン未設定」の案内が出る。
5. マッピング失敗やAIエラー時はUIがクラッシュせず、既存のガイダンス文言が表示される。
6. マッピングと永続化のユニットテストが追加され、テストスイートが実行可能である。

## 未解決事項
- アクティブプランの履歴をどの程度残すか（今回は最新のみを強調表示し、履歴は削除せず保持）。
- 採用プランのローカライズ済み見出しの最終調整（現状は日本語固定）。

## 依存関係
- SwiftDataのModelContainer初期化（`my_traning_appApp`でのモデル登録が必要）。
- 既存のFoundationModelクライアントとエラーハンドリング方針を流用する。
