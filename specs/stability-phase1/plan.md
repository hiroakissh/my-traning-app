# 安定化フェーズ1 実装計画

## コンテキスト
本計画は AI プランニングとワークアウト読み込みフローの安定化フェーズ初回対応をカバーします。既存の SwiftUI ターゲット（`my_traning_app`、`my_traning_appTests`）の範囲で作業を完結させ、新規モジュールは追加しません。

## アプローチ
1. 利用可否ハンドリングの導入
   - `FoundationModelAvailabilityStatus` を定義し、各利用不可理由とユーザー向けメッセージをまとめる。
   - `LiveFoundationModelClient` で利用可否をリクエスト前に確認し、クラッシュの代わりに `FoundationModelError` を返す。
   - `LanguageModelSession` を遅延生成し、ステータス変化後に再評価できるようにする。
2. プランナーでのエラー文言マッピング
   - `AIWorkoutPlanner` に Foundation Model エラーを日本語のガイダンスへ変換するヘルパーを追加する。
   - 既存の未知エラーについては汎用的な案内を維持し、診断用ログを残す。
3. UI メッセージ更新
   - `HomeView` と `PlanningView` で状況に応じた説明（Apple Intelligence の有効化手順など）を表示する。
   - 触っているタイミングで `PlanningView` の重複プレビューを解消する。
4. リソース読み込みの堅牢化
   - `Bundle.decode` を `throws` 化し、記録画面からは `Result` で扱えるラッパーを追加する。
   - `RecordingView` に失敗時のインラインメッセージを実装する。
5. テスト
   - 利用可否マッピングと Bundle デコーダーの振る舞いを検証するユニットテストを追加する。
   - 既存のプランナーテストを拡張し、構造化エラー受信時の文言を検証する。

## フェーズ1 憲法チェック
- ✅ 仕様の目標（クラッシュ経路排除・案内文追加・テスト補強）と整合している。
- ✅ アーキテクチャ境界（サービスは Domain、UI は Presentation、ユーティリティは Utilities）を維持している。
- ✅ 新たなフレームワーク導入や複雑性の増加を避けている。

## 検証計画
- `swift test` を実行し、追加したユニットテストを含めてパスすることを確認する。
- Home/Planning のプレビューでメッセージ表示を目視確認し、必要に応じて後続でスクリーンショットを取得する。
- テストでモックバンドルを利用し、デコーダー失敗時にクラッシュせずハンドリングできることを確認する。

## ロールバック計画
- 実行時に重大な退行が見つかった場合はブランチのコミットをリバートする。スキーマ変更はないため、巻き戻しは容易。
